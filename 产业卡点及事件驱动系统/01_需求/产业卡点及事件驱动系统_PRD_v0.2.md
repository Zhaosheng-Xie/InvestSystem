## 1. 产品裁决

本项目不是继续美化原有投资框架，而是把其中有价值的产业研究能力改造成一套可证伪的交易系统：

`产业上下文 → 产业卡点 → 可投资受益公司 → E0—E7 商业事件 → 四道门 → 可成交价格 → 风险仓位 → 验证与退出`

系统的输出不是“看好某只股票”，而是以下之一：

- `RESEARCH`：值得继续研究，但未取得实盘资格。
- `SHADOW_ONLY`：只允许影子记录，不允许真实仓位。
- `TRADE_READY`：在当前证据和当前可成交价格下通过全部门槛。
- `REJECT`：信息足够作出判断，但至少一道准入门确定未通过，因此不交易。
- `ABSTAIN`：关键事实、经济参数、预期或成交条件无法可靠判断。
- `BLOCKED`：触发治理、合规、数据、流动性或组合硬否决。

`E4` 只是首次获得真实仓位资格的必要条件之一，不是自动买点；它同时是一次强制重新承保点。即使订单真实，若利润不重要、市场已经定价或价格不可接受，仓位仍为零。

## 2. 北极星目标与资金约束

### 2.1 北极星

长期愿景是“从 10 万元到 1,000 万元”，但 100 倍目标不是产品验收指标。系统优先优化：

`长期生存概率 × 可重复优势 × 扣费后复利 × 扩容能力`

禁止用高杠杆、单票豪赌、未来信息、不可成交价格或回测调参代替真实优势。

### 2.2 已确认资金与风险边界

| 项目 | 已确认要求 |
|---|---|
| 初始资金基数 | 10 万元 |
| 最大可承受账户回撤 | 20%，属于生存上限而非操作触发点 |
| 追加资金 | 系统验证有效后最多追加 20 万元 |
| 杠杆与方向 | 首版不使用杠杆、融资融券或做空 |
| 交易品种 | 中国 A 股普通股；MVP 排除 ST/*ST、上市初期新股、长期停牌和无法可靠成交证券 |
| 下单权限 | 人工最终批准；研究 Agent 不得持有券商凭证或提交订单 |
| 持有逻辑 | 中低频事件交易，以可验证催化点为时钟，最长验证窗口暂定 120 个交易日 |

20% 不能用作单笔止损或单笔风险预算。系统必须在达到该上限前分层降险和停机。

## 3. 状态与参数治理

### 3.1 状态含义

| 标签 | 含义 | 能否进入 live |
|---|---|---:|
| `requirements_confirmed` | 用户已经确认的产品需求 | 否 |
| `hypothesis` | 需通过历史与前瞻验证的数值或方法 | 否 |
| `draft` | 尚未完成规格化或评审 | 否 |
| `TBD` | 缺少必要选择或数据 | 否 |
| `approved` | 下游规则经评审并满足回测前置条件 | 仅可进入对应验证阶段 |

### 3.2 版本纪律

- 需求、事件定义、数据字段、门槛、成交模型和退出规则分别版本化。
- 修改任何影响准入、仓位或退出的规则，必须升级策略版本并重跑受影响验证。
- 原始证据和旧判断不可覆盖，只能通过 `supersedes` 建立血缘。
- 不得因样本少或回测结果不理想而静默放宽 E4 或利润门槛。

## 5. 产业上下文包

### 5.1 为什么必须独立建设

研报、财报和上市公司公告是必要输入，但不足以发现产业节点及其真实约束。每条产业链必须先建立带 `as_of` 的“产业上下文包”，系统才允许对链内公司做投资裁决。

### 5.2 最小内容

每个上下文包至少包含：

1. 产品、技术代际、关键指标和产业术语表；
2. `产品—部件—设备—材料—供应商—客户—替代路线` 证据图；
3. 需求来源、客户资本开支、采购模式、部署节奏和领先指标；
4. 认证、送样、定点、中标、扩产、量产、交付和验收周期；
5. 名义产能、有效产能、良率、交期、价格、成本和库存的可得证据；
6. 竞争格局、CR3、客户集中度、切换成本、国产替代与潜在新供给；
7. 产业利润池及其向上市公司收入、增量毛利和现金流的传导桥；
8. 历史阶段、已知反例、证伪条件和不可恢复字段；
9. 来源、发布时间、首次获取时间、版本、置信度和冲突记录；
10. 适用公司清单、排除清单和下一次复核触发器。

### 5.3 来源边界

优先使用：

- 交易所公告、公司定期报告和正式投资者材料；
- 客户采购平台、政府采购合同、招投标和公共资源交易平台；
- 客户资本开支、供应商正式披露和可核验交付信息；
- IEEE/OIF/MSA 等标准组织、行业协会、监管与政府统计；
- 产品规格、认证要求、设备交期、专利及经过交叉验证的产业数据；
- 有明确日期、方法和证据链的证券研究与论文。

券商研报只作为假设、预期和线索来源；营销软文、无原文转述和未证实社交媒体内容不得成为状态升级证据。
Qlib、vn.py、RD-Agent 等 GitHub 项目只用于借鉴 PIT、回测、仿真、Agent 隔离和审计实现，不能成为产业事实、收益有效性或自动下单权限的证据。

### 5.4 决策池

- 全 A 股用于 `discovery_radar`，负责发现新事件。
- 只有已预注册、拥有当时版本上下文包的公司进入 `decision_pool`。
- 池外事件进入 `research_quarantine`；补齐上下文后只能按最新可成交价格重新执行四道门，禁止事后按原事件价格回填。

## 6. 从产业节点到可投资公司

### 6.1 产业卡点门

产业节点必须同时回答：

- 需求是否可核验，而非只有市场空间故事；
- 供给响应是否因认证、设备、工艺、良率、牌照或客户切换而变慢；
- 替代路线是否真实受限；
- 稀缺是否可能持续到下一验证窗口；
- 瓶颈消失的领先信号是什么。

### 6.2 可投资卡点门

产业卡点成立后，还必须证明稀缺利润能归属于目标上市公司。公司映射分为三层：

| 层级 | 定义 | 投资资格 |
|---|---|---:|
| `technical_link` | 技术或产品与节点相关 | 无 |
| `qualified_supplier` | 已进入认证、定点、供应商或交付体系 | 仅研究 |
| `profit_beneficiary` | 份额、价格、增量毛利、现金回收和所有权路径可核验 | 才可进入四道门 |

产业位置、供应商资格或收入增长均不能单独证明股东利润增加。关键字段未知时输出 `UNKNOWN`，不得由 LLM、行业平均数或后见信息补写。

## 7. 商业事件状态机

首版真实仓位准入只由 `E4_public` 启动。业绩预告、认证、扩产、供需和价格信息可以更新产业上下文、E0—E3 研究优先级或 E5/E6 验证，但不能在 E4 前独立产生真实仓位。未来增加其他事件入场路径时，必须建立独立规则版本和重新验证。

### 7.1 E0—E7

| 状态 | 最低含义 | 允许动作 |
|---|---|---|
| `E0` | 产业需求或技术叙事，尚无公司级商业验证 | 观察 |
| `E1` | 产品研发、样品、标准或技术可行性证据 | 观察 |
| `E2` | 客户测试、认证、定点或供应商资格 | 研究 |
| `E3` | 招标、采购意向、框架、预计份额或商业谈判 | 研究、影子准备 |
| `E3.5` | 中标候选/结果/通知等强商业线索，但最低经济义务或生效条件未闭合 | 只允许 paper/shadow |
| `E4` | 已生效且存在可核验最低经济义务的订单或合同 | 首次获得实盘候选资格 |
| `E5` | 实际交付、验收或可核验履约进展 | 可重估、持有、加减仓或退出 |
| `E6` | 收入、增量利润和现金回收得到财务验证 | 可重估或转为基本面仓位 |
| `E7` | 复购/规模化、周期成熟、合同终止或论点完成 | 持有、退出或结束跟踪 |

事件状态与持仓状态必须分离：

- `E0—E3` 的真实仓位恒为零；
- `E3.5` 只能进行影子交易；
- `E4` 只代表可以接受四道门审查，实际仓位仍可为零；
- `E5—E7` 不自动加仓，任何动作都需重新估值和风险审批。

持仓使用独立状态：

| 持仓状态 | 含义 |
|---|---|
| `FLAT` | 实际仓位为零，包括研究、影子、拒绝和等待状态 |
| `STARTER` | E4 后通过四道门形成的风险受限初始仓 |
| `CORE` | E5/E6 新证据确认后重新审批的持仓 |
| `TRIM` | 因价值兑现、风险或证据减弱而进入减仓 |
| `EXIT` | 目标仓位已归零，等待实际成交和对账完成 |

### 7.2 E4 的正式定义

`E4_public` 必须同时满足：

1. 来源属于授权公开来源；
2. 法律主体和上市公司归属关系已经核验；
3. 合同/订单已经签署或正式下达；
4. 已经生效，或实质性生效条件均已完成；
5. 存在可核验的最低金额、数量或不可任意撤销的经济义务；
6. 取消、退货、验收等条款没有把最低义务实质清零。

`公告 ≠ E4`，`无公告 ≠ 无 E4`。中标公示、框架协议、“以实际订单为准”或仍需签署正式合同的材料最多进入 `E3.5`。

如果公开证据足以确认 E4 已发生，但金额、价格或最低数量因保密无法核验，可以记录“事件成立”；其利润门为 `UNKNOWN`，交易结论必须是 `ABSTAIN`。

一个权威原始合同可以建立 E4 候选状态；进入 `TRADE_READY` 仍需至少两条独立公开证据链，其中至少一条为权威原文。同一公告被媒体、研报或聚合器重复转述不构成第二条证据。

### 7.3 合规边界

- 实盘资格只使用 `E4_public`，不得使用未公开重大信息。
- 员工、供应商私聊、闭门材料、付费群、泄露文件或绕过权限取得的信息进入合规隔离区，公开前不得交易。
- AKShare、Tushare 和媒体聚合用于发现、去重和回补，不是最终权威证据。

## 8. E4 发现、时间与证据链

### 8.1 合法的早期发现顺序

1. 客户采购意向、招标、项目审批：`E3/E3.5` 预警；
2. 中标候选、中标结果、中标通知：通常仍为 `E3.5`；
3. 政府采购合同、客户采购平台正式订单；
4. 上市公司或交易对方的交易所正式公告；
5. 后续进展公告、定期报告和实际履约数据。

系统必须同时监控供应商端、客户/采购端和政府采购端。互动问答和调研记录只作辅助核验，不能单独升级 E4。

### 8.2 PIT 时间字段

每个事件至少保留：

~~~text
event_at
source_published_at
first_seen_at
verified_at
trade_eligible_at
~~~

`event_at` 只描述商业事件发生时间，不代表市场已经知道。策略可用时间为：

`knowledge_at = max(source_published_at, first_seen_at, verified_at)`

仅有日期而无可靠时分秒的历史材料，一律按下一交易日可用；更正、撤回和补充公告追加版本，不得回溯修改原始可用时间。

## 9. 决策漏斗与四道门

### 9.1 E4 样本漏斗

所有候选必须逐层计数：

`E3/E3.5 → E4_public → 关键字段完整 → Gate 1—4 → 实际可成交 → 独立完整交易`

每层同时记录通过、拒绝、`ABSTAIN` 和缺失原因，避免只统计最终赢家。

### 9.2 四道门

| Gate | 问题 | 失败结果 |
|---|---|---|
| Gate 1：真实性 | 是否为真实、已生效、最低义务可核验的 E4_public | `REJECT/ABSTAIN/BLOCKED` |
| Gate 2：利润重要性 | 对未来 12 个月归母标准化利润和自由现金流是否足够重要 | `REJECT/ABSTAIN/SHADOW_ONLY` |
| Gate 3：预期差 | 此新增经济信息是否尚未被市场充分定价 | `fully_priced→REJECT；unknown→ABSTAIN` |
| Gate 4：可成交收益 | 首次真实可成交价格下是否仍有足够净收益和赔率 | `REJECT/ABSTAIN` |

只有四门同时通过才能进入 `TRADE_READY`。Gate 之间不得用加权总分相互补偿。
Gate 1—2 形成公司/事件论点，Gate 3—4 形成股票论点，两者必须分别保存。每个 `TRADE_READY` 还必须登记至少两个可观察证伪条件及其 proof window。

## 10. Gate 2：利润重要性与三情景

### 10.1 NTM 利润与现金流桥

每个情景使用同一条传导链：

`NTM 归母增量利润 = NTM 可确认收入 × 增量毛利率 − 增量费用 − 税费 − 少数股东损益`

`NTM 增量自由现金流 = 增量利润 + 非现金项 − 增量营运资金 − 增量资本开支`

关键输入至少包括合同义务、交付节奏、验收、实际价格、增量毛利率、良率/利用率、费用、资本开支、回款、税率和归属比例。合同金额、收入占比或历史综合毛利率只能用于筛选，不能替代利润桥。

### 10.2 10% 的正式分母

`利润重要性 = E4 基准情景 NTM 归母标准化增量利润 ÷ E4 前反事实 NTM 归母标准化利润`

分母必须是：

- 截至 E4 首次公开时点、仅使用当时公开信息；
- 假设该事件未发生时的未来 12 个月归母标准化利润；
- 剔除资产处置、补贴、公允价值变动等非经常性项目；
- 由公司级利润桥建立，一致预期只作交叉验证；
- TTM 只作参考，不直接替代反事实 NTM。

无法可靠建立分母时为 `ABSTAIN`。

### 10.3 情景定义

| 情景 | 定义 | 约束 |
|---|---|---|
| 基准 | 当前公开证据下概率最大的执行路径 | 不是上下行情景的机械中点 |
| 下行 | 有合同、历史或产业依据的合理执行不利路径 | 不是为了让交易过门而美化 |
| 上行 | 需要明确触发器才能实现的积极路径 | 无约束力复购不得提前计入 |
| 压力 | 极端但现实的资本损失/流动性路径 | 仅用于仓位与停机，不替代下行 |

每个关键假设保存：

`source_id｜as_of｜base｜downside｜upside｜trigger｜falsifier｜confidence`

三情景应改变少数承重变量并保持经济关系一致，例如延期通常同时影响利用率、利润率和回款。不得对每个变量独立挑选最有利数值。

### 10.4 Gate 2 通过规则

- 基准情景利润重要性必须达到 `10% [hypothesis]`；输入完整但低于门槛时为 `REJECT`；
- 只有上行情景达到 10% 时不得通过；
- 下行情景不强制达到 10%，但必须可量化并进入仓位与退出判断；
- 概率加权不能用来稀释 Gate 2；
- 关键经济字段缺失时不得用行业平均或 LLM 推断，直接 `ABSTAIN`。

### 10.5 亏损和脆弱利润公司

首版实行双轨：

- `standard_track`：反事实 NTM 标准化利润为正且稳健，可进入四道门；
- `fragile_profit_shadow_track`：利润为负、接近零，或合理的基础业务变化即可使利润翻正/翻负；只建立增量毛利、现金流、资本开支、营运资金和融资需求模型，不取得真实仓位资格。

特殊轨只有经过独立版本、充足样本和单独验证后，才能申请开放实盘。

### 10.6 概率使用

首版不强迫为信息不足的情景赋予精确概率。只有当概率有历史基准、来源和校准方法时，Gate 4 才可显示概率加权结果；一旦使用，互斥情景概率必须合计 100%。主准入仍由基准收益和下行赔率决定。

## 11. Gate 3：重建市场预期

E4 必须按首次公开前的 PIT 信息分类：

| 分类 | 含义 | 是否进入 Gate 4 |
|---|---|---:|
| `unexpected` | 业务、金额、客户、期限或经济义务显著超出公开预期 | 是 |
| `partially_priced` | 市场预期有订单，但实际最低义务或利润贡献更高 | 是 |
| `fully_priced` | 此前公开材料和价格已反映相近经济结果 | 否 |
| `unknown` | 无法可靠重建先验预期 | `ABSTAIN` |

预期重建至少使用：

1. E4 前公告、互动问答、业绩说明会和公司指引；
2. 当时已经发布的券商订单/盈利预期；
3. E3 至 E4 前相对行业和市场的异常收益及成交量；
4. E4 新增的信息量：金额、最低义务、客户、价格、交付期或产能利用率。

E4 后上涨或涨停不能反证“此前已经定价”，但会抬高成交价格，必须在 Gate 4 重新计算剩余收益。

## 12. Gate 4：价值、赔率与验证时钟

### 12.1 估值方法

`情景价值 = 未包含 E4 的基础业务价值 + E4 有限期增量自由现金流现值`

- 基础业务使用 E4 时点可得的标准化盈利和保守估值；
- 单次订单只按可执行期限计入，不赋予无证据永续价值；
- Gate 2 只使用 NTM；Gate 4 只有在最低义务、金额和时间具有合同约束力时，才可折现计入 NTM 以后的有限期现金流；
- 复购只有在公开且有约束力后才进入基准，否则只属于上行情景；
- 基准情景不加入概念热度或无依据估值扩张；
- 禁止把订单利润和“新业务估值”重复计价；
- 基础业务或增量现金流不可可靠估计时为 `ABSTAIN`。

### 12.2 首次可成交价格

`剩余收益空间 = 基准情景价值 ÷ 首次实际可成交价格 − 1`

公告真实且利润重要，不代表任何价格都值得买。价格已经超过基准价值时必须拒绝。

### 12.3 首版准入参数

以下均为 `hypothesis`：

- 扣除费用和滑点后，基准剩余收益空间 `≥15%`；
- `基准收益空间 ÷ |下行情景损失| ≥2`；
- 买入前登记下一个公开可验证催化点；
- 最长验证窗口 `120 个交易日`；
- 只有上行情景满足收益门槛时不得买入。

## 13. 成交与回测真实性

### 13.1 决策时间

`decision_time = 官方来源首次公开可访问时间 + 系统发现/核验延迟`

- 收盘后公告最早在下一交易日成交；
- 盘中公告只有在精确时间戳和分钟数据可靠时才允许盘中模拟，否则顺延；
- 一字涨停、无卖盘、停牌或成交量不足均视为不可成交；
- 首次恢复可成交时重新执行 Gate 3 和 Gate 4；
- 连续 `3 个交易日 [hypothesis]` 仍不能成交，放弃信号。

### 13.2 成交价格与容量

- 优先使用可成交窗口 VWAP 并加入佣金、税费、滑点和冲击；
- 只有日线时使用下一交易日 VWAP，并标记低精度；
- 禁止在开盘、最低或收盘价格中事后择优；
- 模拟订单不超过对应成交窗口金额的 `5% [hypothesis]`；
- A 股 T+1、涨跌停、停牌、最小一手、公司行动和历史交易费用必须按生效版本回放。

### 13.3 最小一手

若 100 股的最小订单已超过风险允许仓位，交易必须跳过，不能为凑一手突破风险预算。

## 14. 仓位与组合风险

### 14.1 E4 初始仓位

`initial_position_value = min（账户净值 × 0.5% ÷ 压力损失率，账户净值 × 5%，流动性容量金额，风险簇剩余容量金额，组合剩余容量金额）`

`initial_weight = initial_position_value ÷ 账户净值`

其中：

- `0.5%` 为单笔账户计划损失预算；
- 压力损失率至少按 `10%` 计算，防止通过乐观压力值放大仓位；
- `min()` 中全部候选约束必须先换算为同一人民币仓位金额；风险簇和组合的剩余损失预算需按同一压力损失率转换，禁止把百分比、损失金额和持仓金额直接比较；
- E4 首次权重不超过 `5%`；
- 只有 E5/E6 新证据增强并重新通过估值与风险门，才可加仓；
- 单一公司总权重不超过 `10%`；
- 跳空和跌停的超额损失必须记录，不能假设止损必然成交。

以上数值均为 `hypothesis`。

### 14.2 风险簇与总风险

| 约束 | 首版假设 |
|---|---:|
| 同一产业/客户/产品价格/政策催化风险簇的计划损失 | ≤1.5% NAV |
| 同一风险簇市值权重 | ≤20% NAV |
| 全部未平仓交易计划损失 | ≤4% NAV |
| 单一公司总权重 | ≤10% NAV |

行业分类不同但依赖同一客户、同一产品价格或同一政策结果的持仓，仍视为同一风险簇。
本表数值均为 `hypothesis`。

### 14.3 市场状态

市场状态只调整风险，不改变 E4 真实性或四道门：

| 状态 | 动作 |
|---|---|
| `NORMAL` | 单笔风险预算可用 0.5% |
| `DEFENSIVE` | 单笔风险降至 0.25%，禁止追加 |
| `CRISIS` | 暂停全部新实盘，只保留研究和影子信号 |

`0.5%/0.25%` 风险预算以及具体指数、市场广度、流动性和波动阈值均为 `hypothesis` 或 `TBD`，必须预注册和回测，禁止盘中主观切换。

### 14.4 组合回撤停机

回撤按账户历史最高净值计算：

| 回撤 | 强制动作 |
|---:|---|
| 8% | 新交易风险由 0.5% 降至 0.25% |
| 12% | 暂停新开仓，只处理已有持仓 |
| 15% | 停止实盘、按可成交条件退出并强制复盘 |
| 20% | 生存上限，不得作为等待触发线 |

`8%/12%/15%` 是首版运营 `hypothesis`；`20%` 是用户确认的生存硬约束，不得为优化回测而放宽。

恢复实盘必须有书面归因、规则检查和人工批准，不能因价格反弹自动恢复。

## 15. 退出与重新承保

任一条件满足即可触发动作：

1. `evidence_exit`：合同取消、验收失败、显著延期、价格/数量下调、客户信用恶化或利润桥失效；
2. `risk_budget_exit`：单笔实际亏损达到建仓时登记的账户损失预算；
3. `time_exit`：120 个交易日内没有出现预登记验证事件，不得临时更换催化点；
4. `value_exit`：价格达到或超过当前基准价值，若无 E5/E6 新证据提升价值则退出。

继续持有前必须回答：“如果现在没有仓位，是否会在当前价格重新买入？”  
价格上涨不能自动提高估值，价格下跌不能降低事实门槛。退出后的反弹不构成当时规则执行错误。

## 18. 样本量与回测设计

### 18.1 样本充分性

- 独立 `E4_public` 少于 30 个：不足以评价 E4 识别体系；
- 任一关键子组少于 15 个：只作描述，不下统计结论；
- 声称策略有效前，至少需要 30 个相互独立、真实可成交并已结束的完整交易；
- 独立性按公司、客户、产业催化和时间风险簇检查，不能把同一订单的多份公告当多个样本。

`30/15` 是首版预登记样本门槛；正式验证开始后冻结，任何修改都必须升级版本并重跑。

若样本不足，按顺序处理：

1. 修复数据覆盖和漏抓；
2. 扩展年份、板块和授权公开来源；
3. 扩展到经济机制相同的相邻产业；
4. 最后才共同评审 E4 定义；若修改，升级版本并全量重跑。

### 18.2 偏差控制

- 2019—2022、2023、2024—2026 分段报告；
- 股票池包含当时全部候选、失败者、退市和被否决公司；
- PIT 强制 `available_at <= decision_at`；
- 使用历史有效交易规则、税费和证券状态；
- 同时报告 `ABSTAIN`、假阳性、假阴性和无法成交样本；
- 对行业、成长、质量、动量、市值和市场 Beta 做归因；
- 记录全部参数搜索，执行参数邻域、消融、PBO/Deflated Sharpe 或等价过拟合审计。

已经参与规则设计的历史年份只能算次级验证；规则冻结后的前瞻数据才是真正未知样本。

### 18.3 首批 golden cases

首批案例只用于检验状态和规则边界，不能预设交易结论：

- 长川科技、新易盛：候选产业卡点与利润受益正例；
- 云南锗业、国电南瑞：产业位置与利润货币化可能分离的反例；
- 利通电子：业务切换导致综合毛利变化的标签反例；
- 永太科技、京东方 A：周期性供需与结构性卡点的边界；
- 云南锗业 `2026-04-04` 公告、京东方 A `2026-05-12` 公告：专门检验“新业务预期、产业相关性、E3/E3.5 与 E4_public 是否被混淆”。

上述公告必须由 AKShare/Tushare 发现后回到官方原文核验，不得根据公司名称或公告标题预判 E4。golden set 至少还应包括 50 个 P0 事件文档、10 个涨跌停/停牌/盘后发布边界案例，以及 5 个修订、重复或多源冲突案例。

## 19. 四级验证与“有效”定义

### 19.1 验证阶梯

1. `research_calibration`：早期样本开发规则，所有修改留版本；
2. `locked_historical_replay`：冻结字段、门槛和退出后做时间顺序回放；
3. `forward_shadow`：规则冻结日起实时登记全部买入、拒绝和 `ABSTAIN`；
4. `small_live_canary`：另行批准后，以较低风险验证延迟、滑点和人工执行。

### 19.2 首版通过线

历史与样本外结果必须同时满足：

- 至少 30 个独立可成交完整交易；
- 扣费后单笔平均期望收益为正；
- 按产业风险簇重采样后，期望收益 95% 置信区间下限大于 0；
- 样本外组合最大回撤不超过 15%；
- 最大盈利交易不超过总净利润的 25%；
- 同时报告绝对收益与适配基准的超额收益。

前瞻与小规模实盘必须满足：

- 影子运行至少 6 个月且不少于 10 个合格信号，两项取更晚者；
- 小规模实盘至少 6 个月且不少于 10 笔已结束交易，两项取更晚者；
- 小规模实盘最大回撤不超过 8%；
- 实际滑点、成本和发现延迟没有系统性超出模型；
- 无未记录人工改规则或选择性跳过信号。

这些数值均为 `hypothesis`；一旦进入正式验证即冻结，修改后重新验证。

## 20. 追加资金与停机

额外 20 万元不得一次投入：

| 阶段 | 新增资金 | 前置条件 |
|---|---:|---|
| 第一批 | 5 万元 | 第 19 节全部验证通过 |
| 第二批 | 5 万元 | 新增后再运行 ≥3 个月且完成 ≥10 笔交易，无规则、成本或回撤恶化 |
| 第三批 | 10 万元 | 再运行 ≥3 个月且再完成 ≥10 笔交易，结果仍在合理验证区间 |

- 资金增加不提高单笔风险比例；
- 组合回撤达到 12% 时冻结后续追加；
- 达到 15% 停机线时未投入资金全部冻结；
- 追加资金只能扩大同一已验证策略，不能同时引入新产业或新规则。

|---|---|
| 可重现 | 同一代码、配置、数据快照和随机种子产生一致正式结果 |
| 可解释 | 所有状态、仓位、退出和拒绝可回到证据、假设、规则与价格 |
| 失败关闭 | 数据过期、冲突、解析低置信、模型缺字段或风险引擎故障时禁止新仓 |
| 安全 | 研究 Agent 无券商凭证、生产写权限和自由文本下单权限 |
| 合规 | 只使用授权公开信息；疑似 MNPI 进入隔离并禁止交易 |
| 可观测 | 记录发现延迟、核验延迟、缺失、冲突、滑点、成本和人工覆盖 |
| 可维护 | 数据源、阈值、费用和状态规则配置化并有版本 |
| 数据质量 | 关键原文 100% 有哈希、时间戳和来源；冲突不得静默覆盖 |
| 人工控制 | 任何 live 输出均需数据快照、规则版本、测试报告和人工批准 |

## 22. MVP 交付顺序

### 阶段 A：冻结需求

- 用户审阅并确认本 PRD；
- 把 `hypothesis` 转写为可回测规则规格；
- 定义产业上下文包、E0—E7、E4_public、四道门和数据 schema。

### 阶段 B：高速光互连上下文包

- 重建 2019—2026 的分期产业图；
- 建立公司映射、证据源、反例和历史候选全集；
- 明确不可恢复字段和 `UNKNOWN/ABSTAIN` 路径。

### 阶段 C：最小可回放管线

`公开来源 → 原文归档 → E3/E3.5/E4 解析 → 利润桥 → 预期重建 → 首次可成交价 → 四道门 → 仓位/退出 → 审计`

### 阶段 D：验证

`golden cases → walk-forward → 次级历史 holdout → 前瞻 shadow → 人工 go/no-go → 小额 canary`

当前交付只完成阶段 A 的需求固化，不代表规则批准、回测通过或允许实盘。

## 23. 下游待规格化事项

下列事项不再改变产品方向，但必须在 `03_规则与规格/` 和 `06_测试与验证/` 中明确：

1. `standard_track` 的利润稳健性判定；
2. 各行业情景变量的历史误差校准方法；
3. 市场 `NORMAL/DEFENSIVE/CRISIS` 的具体指标与阈值；
4. 盘中处理延迟、VWAP 窗口、滑点和冲击模型；
5. 适配市场基准、风险簇和独立样本的算法；
6. E5—E7 的字段、升级、降级和财务验证规则；
7. 数据源授权、历史覆盖、预算和供应商可用性；
8. 券商、人工执行流程与未来 live 合规评审。
9. Gate 3 四档预期分类的观察窗口、量化阈值、最低信息覆盖和冲突处理；
10. Gate 4 基础业务“保守估值”的方法选择、倍数/折现率、价值区间和版本规则。

任何待规格化事项缺失，都不得由实现代码或 LLM 自行决定。

## 24. 最终验收口径

本需求阶段完成的标准是：

1. 系统能明确区分研究框架与可交易系统；
2. 产业上下文、商业状态、四道门、仓位和退出形成闭环；
3. E4 不再被误解为自动买点；
4. 三情景、利润分母、市场预期和首次可成交价格可被历史重放；
5. 所有数值参数的 `hypothesis` 身份清晰；
6. “验证有效”和追加资金有事先冻结的证据门槛；
7. 用户批准本 PRD 后，才进入规则规格和首个产业上下文包。

系统在任何阶段都不能声称“能够保证从 10 万元增长到 1,000 万元”。它只能通过严格的样本外和前瞻证据，逐步证明或否定是否存在可执行的正期望。
