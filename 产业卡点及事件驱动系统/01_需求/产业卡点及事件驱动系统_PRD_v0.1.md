# 产业卡点及事件驱动系统 PRD v0.1

文档状态：`draft for review`  
创建日期：`2026-07-16`  
研究窗口：`2024—2026 为当前规则与近期适应性窗口；长期验证必须向前扩展`  
目标市场：`中国 A 股`  
第一用户：`个人投资者 / PM，低换手、集中研究、人工批准`  
非承诺声明：本文定义研发目标与风险边界，不承诺收益，也不构成个股投资建议或法律意见。

---

## 1. 背景与问题

现有“明准投资研究体系 v2.0”已经能完成产业链卡位、财务过滤、锚池维护、公告/调研/研报监控和反例复盘，但它仍主要是研究系统：能说明“为什么值得研究”，不能稳定回答“此刻是否可交易、应承担多少损失、组合里是不是同一个赌注、证据何时失效”。

现有材料的核心缺口有六个：

1. `产业瓶颈 → 上市公司利润 → 股票超额收益` 之间缺少可证伪的传导链。
2. GPM 被赋予过强裁决权，无法区分原料下跌、产品结构、业务切换、汇率、补贴和真实定价权。
3. 锚池采用“任一条件入池”，混合了结构证据、事件提示、注意力和价格行为。
4. 研究分数与仓位、相关性、流动性、跳空风险之间没有统一约束。
5. 公告、财务、预期修订和交易规则缺少严格的 point-in-time（PIT）版本，历史回测容易使用未来信息。
6. A 股 T+1、涨跌停、停牌、一字板、盘后信息与规则变更尚未成为成交模型的一部分。

因此，本项目的任务不是继续增加指标，而是把研究框架升级为一条可追溯的资金决策链。

## 2. 北极星目标与现实约束

### 2.1 北极星

长期目标是构建一套能够保护本金、复利增长、可扩容且可持续迭代的交易系统。“10 万到 1,000 万”是 100 倍目标，不是验收承诺。

若无新增资金、税费和取款，100 倍所需年化复合收益约为：

| 完成期限 | 所需 CAGR |
|---:|---:|
| 5 年 | 151.2% |
| 10 年 | 58.5% |
| 15 年 | 35.9% |
| 20 年 | 25.9% |

这意味着系统首先要优化“长期生存概率 × 可重复优势 × 可扩容性”，不能以高杠杆、单票豪赌或回测过拟合作为实现路径。

### 2.2 产品目标

- 把产业链卡点观点转换为可核验、可证伪、带时间窗的投资假设。
- 只在结构、事件、预期差、估值/赔率和风险同时过门槛时进入 `Trade-ready`。
- 对证据不足、冲突或不可成交的情形输出 `ABSTAIN`，而不是勉强给分。
- 对每个历史决策回答：“当时知道什么、为什么做、实际能否成交、错在哪里”。
- 建立从研究、回测、paper、shadow 到小额 canary 的版本发布路径。

### 2.3 非目标

- 不预测所有涨停板，也不追求覆盖每一种 A 股风格。
- MVP 不做日内高频、Level-2 微结构、融资融券做空、杠杆或自动实盘。
- 不让 LLM 自由生成订单、修改生产规则、放宽风控或读取券商密钥。
- 不把静态评分、单一财务指标或单篇研报直接转换为仓位。
- 2024—2026 的回放只验证近期数据工程和适应性，不证明跨周期 alpha。

## 3. 核心假设与竞争优势

### 3.1 Alpha 假设

系统拟捕获的不是“高毛利公司”本身，而是下面五层信息差的交集：

1. `结构性稀缺`：认证、设备、工艺、牌照、产能或客户切换造成供给响应迟缓。
2. `领先验证`：下游资本开支、订单、招投标、价格、交期、库存或产能利用率先于财报变化。
3. `事件时点`：公告、业绩预告、量产/认证、重大合同、供需冲击等让市场必须重估。
4. `预期差`：事件带来的盈利变化尚未被一致预期、估值和公告前价格充分反映。
5. `行为与执行`：注意力扩散缓慢，但涨跌停、拥挤和流动性决定能否获得理论收益。

### 3.2 我们希望比竞争者做得更好的地方

- 不是更快读新闻，而是更快把事件挂到产业链、利润桥和证伪条件上。
- 不是给出更高主观分数，而是保留原文、时间戳、版本和反证，使判断可重放。
- 不是买入更多“好公司”，而是拒绝证据不完整、已被定价或无法退出的机会。
- 不是让 AI 直接交易，而是让 AI 提高研究吞吐量，确定性引擎负责状态和风险，人工负责最终批准。

### 3.3 外部证据如何影响设计

- 中国市场存在供应链信息渐进扩散的研究证据，因此产业链图与上下游先行变量值得验证，但不能把相关性直接当成因果和可交易收益。[供应链可预测性研究](https://ideas.repec.org/a/bla/acctfi/v60y2020i2p1531-1562.html)
- 2024 年 A 股 PEAD 研究显示业绩意外与注意力可能共同影响公告后漂移，因此“业绩事件 + 公告后反应”可作为研究支线，但论文收益不能直接外推到本账户。[PEAD 研究](https://www.sciencedirect.com/science/article/abs/pii/S1057521924003922)
- 2025 年发表的深交所公司访问研究发现“异常调研强度”比绝对调研次数更有信息含量，因此原规则“30 日 ≥ 3 次”应改为相对公司历史、行业和月份的异常值，并控制披露时点。[机构调研研究](https://www.cambridge.org/core/journals/journal-of-financial-and-quantitative-analysis/article/abs/investor-corporate-visits-and-predictable-returns/77C958598BB1DC92C46EA32BF252A4B9)
- Qlib 的 PIT 文档明确指出，使用财务数据的最新修订版本回测会造成泄漏，因此 `available_at <= decision_at` 是硬约束。[Qlib PIT 文档](https://qlib.readthedocs.io/en/stable/advanced/PIT.html)

## 4. 用户、使用场景与默认假设

### 4.1 主要用户

- 研究员角色：维护产业链、证据、假设、反证和候选池。
- PM 角色：判断赔率、事件路径、仓位和组合冲突。
- 风险角色：执行硬闸门、损失预算、流动性与回撤约束。
- 复盘角色：比较决策时信息、理论成交、实际成交与结果。

初期四个角色可由同一位用户承担，但系统权限和输出必须分开。

### 4.2 核心使用场景

1. 每日发现新的业绩预告、订单/中标、认证/量产、供需/价格或重大治理事件。
2. 把事件匹配到产业环节和上市公司利润传导链。
3. 对候选生成证据卡、冲突项、情景、催化剂、证伪和风险。
4. 生成 `ABSTAIN / Research / Trade-ready / Blocked` 状态和原因。
5. 生成目标仓位建议，但 MVP 只用于回测和 paper。
6. 每日只显示相对上次判断的 `thesis delta`，降低信息过载。
7. 每周复核组合叙事簇、候选漏斗、数据质量与规则表现。

### 4.3 v0.1 默认假设（待用户确认）

- 资金基数：10 万元。
- 不使用杠杆、融资融券或做空。
- 仅 A 股普通股；MVP 排除 ST/*ST、北交所、新股上市初期和长期停牌证券。
- 持有期以 5—63 个交易日为主，低换手，不做日内回转。
- 最终下单必须人工批准；系统与券商交易网关物理/权限隔离。
- 最大可接受回撤尚未确认，8%/12%/15% 仅作为仿真闸门占位值。

## 5. 术语与状态

### 5.1 关键术语

- `产业卡点`：供给响应慢、替代困难、需求变化可验证，并且稀缺利润有路径传导至目标上市公司的环节。
- `领先证据`：订单、价格、产量、交期、客户资本开支、库存、招投标等先于正式财务确认的数据。
- `事件`：在确定发布日期/发生日后，可能改变盈利路径、时间、概率或市场预期的可识别事实。
- `股票论点`：公司基本面正确之外，当前价格仍存在足够净回报和可成交性。
- `独立证据链`：来源、生成机制或主体不同，不能只是同一公告被媒体、研报重复转述。
- `PIT`：在任一历史决策时刻，只能读取当时已发布、已收到并可供决策的数据版本。
- `ABSTAIN`：因证据不足、冲突、无法定价、无法成交或超出策略能力圈而明确不行动。

### 5.2 生命周期状态机

```text
全市场
  → Eligible Universe
  → Research Pool
  → Underwriting
  → Trade-ready
  → Starter
  → Core
  → Trim / Re-underwrite / Exit

任意状态 ──硬闸门──→ Blocked
证据不足/冲突 ─────→ ABSTAIN
```

所有状态变化都写入不可变 `decision_event`；不得覆盖旧判断。

## 6. MVP 事件范围

### 6.1 P0 事件（必须支持）

| 类型 | 例子 | 核心问题 |
|---|---|---|
| 业绩事件 | 业绩预告、快报、正式财报、盈利修正 | 是否主营驱动、是否超预期、公告后是否仍有赔率 |
| 订单与客户事件 | 重大合同、中标、客户资本开支、订单取消 | 订单是否可执行、占收入比例、毛利与回款如何 |
| 产能与认证事件 | 扩产、投产、量产、首台套、客户认证 | 从计划到收入要多久，供给会否迅速跟进 |
| 供需与价格事件 | 产品涨价、交期、库存、开工率、原料冲击 | 利润留在哪个环节，持续时间和替代路线是什么 |
| 治理与合规事件 | 立案、非标审计、占款担保、ST/退市风险 | 是否触发硬否决或冻结 |

### 6.2 P1 事件（MVP 后）

- 并购重组、分拆、回购、增减持、解禁、指数调整和政策冲击。
- 这些事件先进入监控，不与 P0 混用同一概率模型。

### 6.3 明确排除

- 未证实社交媒体消息、所谓“产业链小作文”、无原文的转述。
- 仅因概念归属、连续涨停、热搜或大 V 推荐而形成的候选。
- 无法确定发布日期和当时可得时间的数据。

## 7. 决策门槛

### 7.1 Eligible Universe

证券进入研究漏斗前必须满足：

- 当日板块、上市状态、ST/退市、停复牌、涨跌幅制度有 PIT 记录。
- 计划仓位可在预设天数内退出，不能把零成交或一字板当成可成交。
- 公司行动、复权和证券代码映射可追溯。
- 无治理、数据、执行硬否决。

### 7.2 Research Pool

至少有一条领先证据，并通过基础质量检查：

- 可核验的订单、价格、产量、交期、客户资本开支或库存拐点；或
- 主营驱动的业绩预告/快报/财报意外；或
- 多家分析师的 PIT 预期上修；或
- 产品级供需表显示由松转紧且供给响应时滞可核验。

调研、研报、热度和技术形态只能增加研究优先级，不能单独进入 Trade-ready。

### 7.3 Trade-ready

必须同时满足：

1. 至少两条独立证据链，其中至少一条为权威原始来源。
2. 产业卡点、需求、利润传导和替代路径均有文字化因果链。
3. 公司论点与股票论点分开。
4. 基准/上行/下行情景及概率是显式判断，合计 100%。
5. 至少一个带日期或窗口的下一催化剂。
6. 至少两个可观察证伪条件和 proof window。
7. 公告前价格、当前价格、流动性和成本后净回报通过门槛。
8. 单票、叙事簇、流动性、跳空和回撤约束全部通过。
9. 数据无未解决重大冲突，所有关键字段可回到原文位置。

不满足时输出明确 block reason 或 `ABSTAIN`。

## 8. 功能需求

### 8.1 数据与证据

| ID | 优先级 | 需求 | 验收 |
|---|---|---|---|
| FR-DATA-001 | P0 | 存档公告/财报原文、附件、URL、内容哈希与获取时间 | 任一关键事实可回到原文及证据片段 |
| FR-DATA-002 | P0 | 维护 `published_at/received_at/available_at/decision_at` | 回放查询强制 `available_at <= decision_at` |
| FR-DATA-003 | P0 | 财务和事件保留修订版本，不覆盖旧值 | 可查询任一时点当时可知版本 |
| FR-DATA-004 | P0 | 证券状态、公司行动、交易规则按生效日版本化 | 历史回放不套用 2026 当前规则 |
| FR-DATA-005 | P0 | 关键事件双链路获取或原文复核 | 冲突进入队列，不静默覆盖 |
| FR-DATA-006 | P1 | 数据质量看板：缺失、延迟、冲突、解析失败、源健康 | 每日输出数据健康摘要 |

巨潮资讯是深交所法定信息披露平台，应作为原文入口之一，而 AKShare/Tushare 主要用于发现、提速和补充，不能替代关键事实的原文归档。[巨潮资讯](https://www.cninfo.com.cn/)

### 8.2 产业链与卡点

| ID | 优先级 | 需求 | 验收 |
|---|---|---|---|
| FR-IND-001 | P0 | 建立 `产品—环节—供应商—客户—替代路线` 证据图 | 每条边有来源、时间和置信度 |
| FR-IND-002 | P0 | 分开记录“产业瓶颈存在”与“利润归属于目标公司” | 不允许用同一个分数替代两项判断 |
| FR-IND-003 | P0 | 记录认证周期、扩产周期、CR3/供应商集中、替代方案 | 缺失字段显式显示，不由 LLM 补写 |
| FR-IND-004 | P1 | 下游领先指标映射到目标公司的收入/毛利桥 | 可展示传导时滞与主要敏感项 |

### 8.3 事件解析与研究

| ID | 优先级 | 需求 | 验收 |
|---|---|---|---|
| FR-EVT-001 | P0 | 将文档解析为结构化事件：主体、类型、金额/产能、时间、条件、来源 | 通过标注集的字段级精确率/召回率测试 |
| FR-EVT-002 | P0 | 区分 `Fact / Assumption / Derived / Judgment` | 四类内容分字段保存 |
| FR-EVT-003 | P0 | 合并重复转述，保留共同原始来源 | 同一公告不被计为多条独立证据 |
| FR-EVT-004 | P0 | 生成支持证据、反对证据、冲突和待核问题 | 每个候选至少有一项 red-team 输出 |
| FR-EVT-005 | P0 | 事件只改变相关假设，不触发直接下单 | 输出 ResearchProposal/DecisionCandidate，不输出 Order |

### 8.4 评分、情景与状态

| ID | 优先级 | 需求 | 验收 |
|---|---|---|---|
| FR-DEC-001 | P0 | 分模块呈现结构稀缺、需求验证、货币化、资本效率、外部确认和风险 | 不使用未经校准的总分决定仓位 |
| FR-DEC-002 | P0 | GPM 必须与价格/量/结构/成本拆桥、增量毛利率和现金转化一起解释 | GPM 单项变化不能触发 Trade-ready |
| FR-DEC-003 | P0 | 输出基准/上行/下行情景、时点、终值/回报和证伪 | 概率合计 100%，假设可编辑可追溯 |
| FR-DEC-004 | P0 | 输出市场状态概率，但状态只调整风险和门槛 | 状态不得覆盖公司硬证据或硬否决 |
| FR-DEC-005 | P0 | 支持 `ABSTAIN` 与明确阻断原因 | 缺关键输入时默认失败关闭 |

### 8.5 风险与组合

| ID | 优先级 | 需求 | 验收 |
|---|---|---|---|
| FR-RISK-001 | P0 | 先算论点失败/跌停/流动性退出压力损失，再定仓位 | 每个仓位有损失预算依据 |
| FR-RISK-002 | P0 | 单票、叙事簇、行业、因子、流动性、跳空、回撤多重上限取最小值 | 任一闸门可阻断目标仓位 |
| FR-RISK-003 | P0 | 硬否决与软风险分离 | 软风险只降权/提门槛，硬否决冻结 |
| FR-RISK-004 | P0 | 只有新证据增强才允许加仓 | “价格下跌/摊低成本”不是合法原因 |
| FR-RISK-005 | P0 | 回撤阈值只允许减少风险，恢复需人工批准 | 无自动加风险路径 |

仿真占位参数：常规单票上限 10% NAV、叙事簇 25%、Starter 为目标仓位 1/3、新开核心仓压力损失预算 50—75bp NAV、回撤黄/橙/红灯 8%/12%/15%。全部标记 `draft`；任何 draft 参数存在时禁止 live。

### 8.6 回测、执行与审计

| ID | 优先级 | 需求 | 验收 |
|---|---|---|---|
| FR-BT-001 | P0 | 事件驱动 PIT 回放，信号使用下一可交易时点 | 盘后公告不能按当日收盘成交 |
| FR-BT-002 | P0 | 模拟 T+1、涨跌停、停牌、无对手盘、退市、费用、滑点与冲击 | 不可成交订单保持未成交或延迟 |
| FR-BT-003 | P0 | 保存所有实验、参数、样本、提示词、失败结果和运行清单 | 可重现任一正式结果 |
| FR-BT-004 | P0 | 研究、paper、shadow、live 四环境隔离 | 研究凭证不能访问交易网关 |
| FR-EXEC-001 | P0 | 生成签名版 TargetPortfolio 与订单草案，不自动提交 | 人工批准记录为必填 |
| FR-AUDIT-001 | P0 | 对账理论目标、模拟成交、实际成交、费用和滑点 | 每日产生不可变审计记录 |

[证监会规定](https://www.csrc.gov.cn/csrc/c100028/c7480577/content.shtml)要求程序化交易遵循报告、监测与系统安全等安排；沪深交易所已发布实施细则。因此，任何自动生成并下达交易指令的生产版本，上线前必须与券商及专业合规人士确认报告、账户、系统接入和测试要求。MVP 不接自动实盘。

## 9. A 股市场规则需求

交易规则必须配置化并按 `effective_from/effective_to` 管理，至少覆盖：

- 当日买入股票通常次一交易日方可卖出。
- 主板、创业板、科创板、风险警示和新股不同涨跌幅制度。

- 公司行动、除权除息、可卖数量、冻结资金、最低申报单位和价格变动单位。
- 佣金、最低佣金、印花税、经手费、证管费、过户费、滑点和冲击成本的历史版本。
- 盘后固定价格交易的适用品种和生效日期。

上交所 2026 修订规则于 2026-07-06 生效，并扩大盘后固定价格交易范围、调整部分风险警示股票涨跌幅；这证明“今天的规则不能回填历史”。[上交所说明](https://www.sse.com.cn/aboutus/mediacenter/hotandd/c/c_20260424_10816474.shtml)；[深交所 2026 交易规则 PDF](https://docs.static.szse.cn/www/lawrules/rule/trade/current/W020260424690713155663.pdf)

## 11. 非功能需求

## 12. 验证与成功指标

### 12.1 数据/工程门槛

- 关键事实原文可追溯率：`100%`。
- PIT 回放违规数：`0`。
- 正式运行可重现率：`100%`。
- P0 事件标注集上，事件类型精确率 `≥95%`；金额、时间、产能、条件等关键字段精确率 `≥90%`。
- 不可成交场景误成交数：`0`。
- 数据冲突静默覆盖数：`0`。

### 12.2 研究门槛

- 每个 Trade-ready 候选两条独立证据链覆盖率：`100%`。
- 公司论点/股票论点分离率：`100%`。
- 情景概率合计 100% 与证伪条件完整率：`100%`。
- `ABSTAIN`、Research、Trade-ready 的后续表现和阻断原因分层统计。
- 记录假阳性、假阴性、拒绝率、证据冲突率和解析人工修订率。

### 12.3 策略门槛

收益不设先验硬承诺。正式报告必须同时提供：

- 成本后 CAGR、相对基准收益、最大回撤、Calmar、CVaR。
- 命中率、盈亏比、持有期、换手、滑点、冲击与容量。
- 按事件、市场状态、行业、市值、流动性和叙事簇分解。
- 收益是否集中在少数股票、月份、产业或单一市场阶段。
- 参数邻域、消融、起止日期、极端值、退市和涨跌停敏感性。
- 多重试验记录、PBO/Deflated Sharpe 或等价过拟合审计。[Deflated Sharpe Ratio](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=2460551)

### 12.4 上线门槛

```text
需求与规则批准
→ 数据/PIT/成交单元测试
→ 事件 golden set
→ 时间顺序 walk-forward
→ 冻结 holdout
→ paper 至少 3—6 个月且覆盖一个完整财报周期
→ shadow 至少 3—6 个月
→ 人工 go/no-go
→ 小额 canary
```

90 天 MVP 的完成条件是“可回放、可审计、可 paper”，不是进入 live。

## 13. Golden cases 与反例

首批 golden cases 来自用户材料，尚需回到公告和历史行情独立复核：

- 长川科技、新易盛：候选“真卡点”正例。
- 云南锗业、国电南瑞：产业位置成立但货币化/定价权不足的反例。
- 利通电子：业务切换导致 GPM 变化，传统行业标签漏检的反例。
- 永太科技、京东方 A：周期/堡垒与结构性卡点的边界案例。
- 商业航天案例：基本面框架在题材主导期的失效案例。

验收时不得只使用成功样本。至少建设：

- 50 个 P0 事件文档标注集；
- 20 个完整决策回放，其中正例、假阳性、假阴性和 ABSTAIN 各有覆盖；
- 10 个涨跌停/停牌/盘后公告/规则切换的成交边界案例；
- 5 个数据修订、重复公告或多源冲突案例。

## 14. 90 天 MVP

### 0—30 天：冻结需求与“当时知道什么”

- 评审本 PRD，确认资金、回撤、持有期、杠杆、数据和券商约束。
- 完成 Evidence、Event、SecurityStatus、Decision、TargetPortfolio、RunManifest schema。
- 存档 P0 事件原文并建立 PIT 时间、哈希和修订血缘。
- 把原始材料中的案例改造成带反例的 golden cases。

### 31—60 天：最小研究与风险内核

- 打通 P0 事件发现、解析、去重、证据卡和产业链匹配。
- 实现确定性状态机、ABSTAIN、情景、证伪和 draft 风险规则。
- 完成 A 股 T+1、涨跌停、停牌、费用和下一可交易时点回放。
- 回放 2024—2026；明确其仅为近期工程/适应性验证。

### 61—90 天：paper/shadow 准备

- 接入模拟目标组合—订单草案—模拟成交—对账链。
- 每日生成 thesis delta；每周生成候选漏斗、风险和数据质量复盘。
- 完成泄漏、消融、成本、容量、跳空和压力测试。
- 第 90 天只做 go/no-go 评审，默认继续 paper，不进入 live。

## 15. 关键依赖与选型原则

- Qlib 可承担 PIT 研究、实验记录、模型与回测的参考实现，但官方公共数据质量说明也提示应自备高质量数据。[Qlib](https://github.com/microsoft/qlib)

- RD-Agent 可借鉴其研究提案—实现—评估循环，但只允许在隔离研究层生成候选因子/实验，不拥有生产决策权。[RD-Agent](https://github.com/microsoft/RD-Agent)
- 数据供应商用于提速，不自动成为权威事实源；授权、接口稳定性、历史修订和商用条款需单独评估。

## 17. v0.1 产品裁决

本系统第一阶段应定位为：

> 一个以权威原始证据和 PIT 数据为底座、以产业卡点与事件路径为研究核心、以 ABSTAIN 和损失预算为安全机制、以人工批准为最终控制点的 A 股中低频决策系统。

它的首要成功不是“回测收益漂亮”，而是以下三件事按顺序成立：

1. 任一历史时点只使用当时可知信息；
2. 理论信号在真实交易规则和成本下能够成交；
3. 样本外净收益来自可解释、可重复且未被单一行情阶段垄断的优势。
