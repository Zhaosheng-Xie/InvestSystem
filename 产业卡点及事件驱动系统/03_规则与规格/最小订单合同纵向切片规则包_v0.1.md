## 5. 公共数值、时间与缺失语义

### 5.1 Decimal 与单位

以下规则均为待批准草案：

1. 金额、价格、数量、比例、税率、成本率、折现输入和计算结果一律使用十进制字符串，禁止二进制浮点数。
2. 每个金额必须显式携带 `currency`；本合成场景只使用 `CNY`。
3. 每个数量必须显式携带 `unit`；不同单位不得直接比较。
4. 比例使用无量纲十进制，例如 `0.35` 表示 35%，不得混用 `35` 与 `0.35`。
5. 中间计算使用任意精度 Decimal，不做中间舍入。
6. 门槛比较使用未舍入值；展示值拟保留 6 位小数并使用 `ROUND_HALF_EVEN`。
7. `null/UNKNOWN` 与数值零严格区分。缺失、保密或不可核验不得写成零。
8. 所有公式必须先完成币种、单位、税前/税后和归属口径一致性校验；否则为 `ABSTAIN`，不得继续运算。

### 5.2 PIT

被策略使用的每条知识必须满足：

```text
available_at <= strategy_input_ref.knowledge_cutoff <= decision_at
```

若存在策略侧人工复核时点，则：

```text
strategy_usable_at = max(available_at, strategy_reviewed_at)
strategy_usable_at <= decision_at
```

附加约束：

- `available_at` 原样使用输入中的提供方 PIT 值，策略不得重算或提前。
- 只有日期、缺少可靠时间、时间冲突或超出知识截止时间时，不得自行假定“下一交易日可用”。
- 首次可成交价格只能在其市场观察已经可用后进入 Gate 4。
- 相同 fixture、规则、代码、显式时钟和随机种子必须产生相同结果与 `replay_hash`。

## 6. 证据独立性与事实类型

### 6.1 独立证据链草案

`TRADE_READY` 拟要求至少两条独立公开证据链，其中至少一条为权威原文。两条链同时满足：

1. `source_document_id` 不同；
2. 发布责任主体不同；
3. 证据的原始取得链不同；
4. 不是同一原文的转载、镜像、摘要、重复公告或同一材料的机器转述；
5. 每条链都有独立的 Evidence/Fact ID、PIT 时间和内容哈希；
6. 至少一条链直接支持签署/下达、生效和最低经济义务，不得两条都只支持产业背景。

本合成场景拟使用：

```text
SYN-EVIDENCE-CHAIN-SELLER-001
  发布主体：合成上市公司信息披露主体
  角色：权威原文

SYN-EVIDENCE-CHAIN-BUYER-001
  发布主体：独立合成采购方
  角色：采购结果与最低义务交叉验证
```

### 6.2 Fact、Assumption、Derived、Judgment 分离

- `Fact`：输入中已验证的合成事实及其证据引用。
- `Assumption`：估值、费用、滑点、收入确认节奏等显式场景假设。
- `Derived`：由固定公式计算的利润、FCF、重要性、收益和赔率。
- `Judgment`：E 状态、Gate 结果、预期分类和最终决策状态。

四类对象不得互相覆盖。Assumption 必须有 `assumption_id`、`as_of`、场景、来源理由和证伪条件；Judgment 不得伪装成输入 Fact。

## 8. E3.5 与 E4_public

### 8.1 `S2B-EVT-001`：E3.5 草案

当存在正式且较强的商业线索，但下列任一闭环缺失或不能可靠判断时，事件为 `E3.5`：

- 尚未签署或正式下达；
- 尚未生效，或实质性生效条件未完成；
- 最低金额、最低数量或不可任意撤销的经济义务不存在；
- “以实际订单为准”，采购方可无条件不下单；
- 取消、退货或验收条款可把最低义务清零。

E3.5 的最终状态为 `SHADOW_ONLY`，`position_state=FLAT`。它不得因公告标题、合作意向、预计份额、市场热度或未来复购想象升级为 E4。

### 8.2 `S2B-EVT-002`：E4_public 草案

E4_public 必须同时满足：

1. 引用审核状态合格的授权公开证据；
2. 卖方法律主体与上市公司利润归属关系可核验；
3. 合同/订单已经签署或正式下达；
4. 已经生效，或全部实质性生效条件已经完成；
5. 存在可核验的最低金额、最低数量或不可任意撤销的经济义务；
6. 取消、退货、验收等条款没有把最低义务实质清零。

规则为严格 AND，不得用总分、置信度或其他字段补偿。一个权威合同可建立 E4 候选；取得 `TRADE_READY` 仍需满足两条独立证据链和全部四门。

### 8.3 E4 成立但经济量未知

若最低数量或其他不可撤销义务足以确认 E4，但价格、金额或收入确认节奏因保密而不可核验：

- 事件状态仍可为 E4；
- Gate 1 可通过；
- Gate 2 必须 `ABSTAIN`；
- 不得用行业 ASP、管理层模糊措辞或 LLM 估值补齐。

## 9. 四道门

### 9.1 `S2B-G1-001`：Gate 1 真实性

Gate 1 检查：

- E4_public 六项 AND；
- 公司利润归属路径；
- 至少一条权威原文；
- 对 `TRADE_READY` 而言至少两条独立公开证据链；
- PIT、授权和重大冲突状态。

结果草案：

| 条件 | Gate 1 结果 |
|---|---|
| E3.5 条件成立 | `SHADOW_ONLY` |
| E4 六项成立且证据要求满足 | `PASS` |
| 信息完整且能确定 E4 不成立 | `REJECT` |
| 关键商业事实缺失或冲突，不能可靠判断 | `ABSTAIN` |
| 输入、授权、合规或治理硬失败 | `BLOCKED` |

### 9.2 `S2B-G2-001`：Gate 2 利润重要性

拟议公式：

```text
ntm_incremental_parent_normalized_profit
  = ntm_recognizable_revenue * incremental_gross_margin_rate
  - incremental_operating_expense
  - incremental_tax_and_surcharges
  - minority_interest_deduction

ntm_incremental_free_cash_flow
  = ntm_incremental_parent_normalized_profit
  + incremental_non_cash_items
  - incremental_working_capital
  - incremental_capex

profit_materiality
  = ntm_incremental_parent_normalized_profit
  / counterfactual_ntm_normalized_parent_profit_base
```

窄版 `standard_track` 拟要求：

- 基准和下行情景的反事实 NTM 标准化归母利润都大于零；
- 分母来自公司级反事实利润桥，不以 TTM 或一致预期直接替代；
- 不拟议未经批准的“接近零”数值阈值；完整稳健性定义留待 Stage 4。

拟议门槛和结果：

| 条件 | Gate 2 结果 |
|---|---|
| 基准情景 `profit_materiality >= 0.10` 且关键字段完整 | `PASS` |
| 字段完整且基准情景 `< 0.10` | `REJECT` |
| 只有上行情景达到 `0.10` | `REJECT` |
| 最低金额/价格、交付、毛利率、费用、税费、归属或分母不可可靠建立 | `ABSTAIN` |
| 不满足窄版 standard track，但可进入脆弱利润观察 | `SHADOW_ONLY` |

`0.10` 仍是待所有者批准的 Stage 2B 验证阈值，不得在批准前加载。

### 9.3 `S2B-G3-001`：Gate 3 窄版预期分类

Stage 2B 只拟议可用精确关系判断的最窄分类，不定义完整历史观察窗口、异常收益阈值或研究预期模型。

预期关键元组：

```text
counterparty_scope
product_scope
currency
binding_minimum_amount_or_quantity
effective_period
material_conditions
```

分类草案：

| 条件 | 分类 | Gate 3 结果 |
|---|---|---|
| 有明确公开证据表明先验最低义务为零，E4 首次产生正的绑定最低义务 | `unexpected` | `PASS` |
| 先验最低义务大于零但严格小于 E4，且其余关键元组一致 | `partially_priced` | `PASS` |
| 先验与 E4 的关键元组完全相同 | `fully_priced` | `REJECT` |
| 先验快照缺失、冲突、不可 PIT 重建或只有“未找到资料” | `unknown` | `ABSTAIN` |
| 先验高于实际或关系不属于本窄规则 | `unknown` | `ABSTAIN` |

本阶段不使用模糊容差；不能严格比较时一律 `unknown`。E4 后上涨不得反推 E4 前预期，但首次可成交价格必须进入 Gate 4。

### 9.4 `S2B-G4-001`：Gate 4 可成交收益

拟议公式：

```text
first_executable_market_cap
  = first_executable_price * fully_diluted_shares

base_scenario_equity_value
  = base_business_equity_value
  + event_finite_life_incremental_fcf_present_value

explicit_friction_rate
  = explicit_cost_rate + explicit_slippage_rate

net_base_remaining_return
  = base_scenario_equity_value / first_executable_market_cap
  - 1
  - explicit_friction_rate

net_downside_return
  = downside_scenario_equity_value / first_executable_market_cap
  - 1
  - explicit_friction_rate

downside_loss
  = abs(min(0, net_downside_return))

reward_to_downside
  = net_base_remaining_return / downside_loss
```

若 `downside_loss <= 0`，本窄版不把赔率设为无穷大，而是 `ABSTAIN`，等待完整规则处理。

拟议门槛和结果：

| 条件 | Gate 4 结果 |
|---|---|
| `net_base_remaining_return >= 0.15` 且 `reward_to_downside >= 2.00` | `PASS` |
| 所有字段完整，但任一门槛未达到 | `REJECT` |
| 基础业务价值、有限期事件 FCF 现值、下行价值、股数、首次可成交价格或摩擦率缺失 | `ABSTAIN` |
| 只有上行情景达到收益门槛 | `REJECT` |

此外必须在买入候选形成前登记下一个公开可验证点，且本合成切片拟要求 `next_verification_trading_days <= 120`；缺失为 `ABSTAIN`，超过 `120` 为 `REJECT`。`120` 仍是待批准 hypothesis，仅适用于 Stage 2B 合成验证。

基准场景手算锚点：

```text
first_executable_market_cap = 8.00 * 1000000000 = 8000000000
base_scenario_equity_value = 8900000000 + 600000000 = 9500000000
explicit_friction_rate = 0.0020 + 0.0030 = 0.0050
net_base_remaining_return = 9500000000 / 8000000000 - 1 - 0.0050 = 0.1825
net_downside_return = 7400000000 / 8000000000 - 1 - 0.0050 = -0.0800
downside_loss = 0.0800
reward_to_downside = 0.1825 / 0.0800 = 2.28125
```

`0.15`、`2.00`、成本率、滑点率和场景价值均未获批准，不是默认生产参数。

## 10. 结果聚合、优先级与短路

### 10.1 评估顺序

拟议固定顺序：

```text
输入与治理准入
→ E3.5/E4_public
→ Gate 1
→ Gate 2
→ Gate 3
→ Gate 4
→ 最终 DecisionState
```

### 10.2 最终结果

| 条件 | 最终结果 |
|---|---|
| 输入/治理硬失败 | `BLOCKED` |
| 事件只到 E3.5 | `SHADOW_ONLY` |
| 任一已评估 Gate 明确 `REJECT` | `REJECT` |
| 尚无明确失败，但任一必要 Gate 为 `ABSTAIN` | `ABSTAIN` |
| 脆弱利润观察轨触发且无硬失败 | `SHADOW_ONLY` |
| E4 成立且四门全部 `PASS` | `TRADE_READY` |

短路规则草案：

1. `BLOCKED` 在策略前发生时，策略函数调用次数必须为零。
2. E3.5 确认后不评估 Gate 2—4。
3. 任一 Gate `REJECT/ABSTAIN/SHADOW_ONLY/BLOCKED` 后，后续 Gate 不再评估。
4. 已有明确 `REJECT` 时不因未运行的后续 Gate 改成 `ABSTAIN`。
5. 未评估不等于 `PASS`、`REJECT`、`ABSTAIN` 或 `BLOCKED`。

### 10.3 GateResult 契约缺口

当前 GateResult draft 只有业务结果，没有“未评估”状态。拟议升级为：

```text
evaluation_state = evaluated | not_evaluated
outcome = PASS | REJECT | ABSTAIN | BLOCKED | SHADOW_ONLY | null
```

当 `evaluation_state=not_evaluated` 时，`outcome=null` 且必须记录 `short_circuit_reason_code`。在机器契约升级前，不得伪造后续 Gate 结果。

### 10.4 合成 TRADE_READY 的持仓语义

即使四门全部通过，Stage 2B 合成结果仍必须：

```text
decision_state = TRADE_READY
position_state = FLAT
target_weight = 0 or null
approved_weight = 0 or null
actual_weight = 0 or null
approver = null
```

它只证明规则路径可达，不表示获得 paper、shadow、live 或真实仓位权限。

同理，本阶段的 `SHADOW_ONLY` 只是 research 运行中的决策状态标签，不授权 `run_mode=shadow`，也不产生影子仓位或执行记录。

## 12. StrategyRunManifest、DecisionRecord 与 replay_hash

### 12.1 StrategyRunManifest

合成 run 必须固定：

- 合成 `strategy_input_ref` 的五字段；
- `fixture_id`、fixture 版本和规范哈希；
- 策略 ID/版本、规则包 ID/版本和草案状态；
- 代码提交、配置哈希、环境锁哈希；
- 注入时钟、随机种子、`research` run mode 和 `validation_only=true`；
- Stage 2A admission 或显式合成 harness 的路径标识，二者不得混淆。

### 12.2 DecisionRecord

每个正常合成策略 case 至少保存：

- event state、decision state、position state；
- supporting/conflicting Fact 与 Evidence ID；
- 每个 Gate 的评估状态、结果、规则 ID/版本和原因码；
- Fact/Assumption/Derived/Judgment 分离记录；
- 利润桥、情景、预期分类和估值；
- 首次可成交时点、价格、费用和滑点；
- 至少两个可观察证伪条件；
- 合成标识、草案状态、不可交易声明；
- `replay_hash`。

输入硬失败 case 只写准入/运行失败审计，不伪造已经执行策略的 DecisionRecord。

### 12.3 replay_hash

`replay_hash` 覆盖：

```text
规范化合成输入身份与内容
规则包 ID/版本/状态
代码提交
配置与显式参数
注入时钟
随机种子
确定性策略输出（排除 replay_hash 自身）
```

观察 ID、实际墙上时钟、临时路径和测试运行顺序不得进入确定性身份。相同输入和版本重复运行必须得到相同 `replay_hash`；任何业务字段或规则变化必须改变它。

## 15. 明确禁止默认的参数和判断

在所有者批准和后续版本化规格出现前，代码不得自行决定：

- Gate 2 的利润阈值、`standard_track` 稳健性或“接近零”定义；
- Gate 3 的观察窗口、显著性、异常收益/成交量阈值、冲突处理或模糊匹配容差；
- Gate 4 的估值倍数、折现率、永续增长率、成本、滑点、价值区间或价格窗口；
- 行业 ASP、毛利率、税率、费用率、交付率、验收率、归属比例或现金回收率；
- 证据独立性、证据置信度或冲突解决阈值；
- Decimal 精度、舍入、币种转换或单位换算；
- 首次可成交价、VWAP 窗口、连续不可成交天数或容量上限；
- 市场 `NORMAL/DEFENSIVE/CRISIS`、仓位、风险簇、退出或加仓规则；
- 缺失值是零、均值、行业代理还是可忽略；
- 真实 Context Pack 缺少正例时应放宽 E4 或四道门。

任何未明确批准的值只能保持 `UNKNOWN/TBD` 并导致相应 `ABSTAIN` 或 `BLOCKED`，不能成为隐藏默认值。
